# 三层记忆架构设计方案

## 1. 整体架构

```
┌─────────────────────────────────────────────────────────────────────┐
│                         用户请求进入                                  │
└──────────────────────────────┬──────────────────────────────────────┘
                               │
                               ▼
┌─────────────────────────────────────────────────────────────────────┐
│                       Memory Router                                   │
│          (根据意图 + session状态，决定从哪些层读取记忆)                  │
│                                                                       │
│  规则：                                                               │
│  ├── 工作记忆: 始终读取（当前推理上下文）                               │
│  ├── 短期记忆: session已有历史 → 读取最近N轮                           │
│  └── 长期记忆: 涉及偏好/历史/知识 → 按需检索                           │
└───────────┬───────────────────┬────────────────────┬────────────────┘
            │                   │                    │
            ▼                   ▼                    ▼
┌──────────────────┐ ┌──────────────────┐ ┌────────────────────────────┐
│    工作记忆       │ │    短期记忆       │ │        长期记忆             │
│  (进程内 dict)   │ │    (Redis)       │ │                            │
│                  │ │                  │ │  ┌─ 知识库 (Chroma RAG)    │
│  • 当前推理状态   │ │  • 最近20轮对话   │ │  ├─ 用户画像 (PG)          │
│  • 路由决策上下文 │ │  • TTL 30min     │ │  ├─ 对话摘要归档 (PG)      │
│  • 子Agent中间结果│ │  • 滑动窗口淘汰   │ │  └─ 旅行历史 (PG)         │
│                  │ │  • 降级→内存dict  │ │                            │
└──────────────────┘ └──────────────────┘ └────────────────────────────┘
```

## 2. 存储层职责划分

```
┌─────────────────────────────────────────────────────────────────────┐
│                        PostgreSQL                                     │
│                   (持久化，给用户看 + 给系统用)                         │
├─────────────────────────────────────────────────────────────────────┤
│  chat_sessions        — 会话列表（用户打开页面看到的）                  │

├─────────────────────────────────────────────────────────────────────┤

│                         Chroma                                        │

├─────────────────────────────────────────────────────────────────────┤
│  travel_knowledge         — 旅游攻略文档（现有，不动）                  │
```

## 3. PostgreSQL 表设计

```sql
-- 1. 会话表
CREATE TABLE chat_sessions (
    id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id       VARCHAR(64) NOT NULL,
    title         VARCHAR(200),       -- 自动生成："杭州3日游规划"
    created_at    TIMESTAMP DEFAULT NOW(),
    updated_at    TIMESTAMP DEFAULT NOW()
);

-- 2. 消息表
CREATE TABLE chat_messages (
    id            BIGSERIAL PRIMARY KEY,
    session_id    UUID REFERENCES chat_sessions(id),
    role          VARCHAR(20) NOT NULL,  -- user / assistant / system
    content       TEXT NOT NULL,
    metadata      JSONB,                 -- 工具调用记录、Agent上下文等
    created_at    TIMESTAMP DEFAULT NOW()
);
CREATE INDEX idx_messages_session ON chat_messages(session_id, created_at);

-- 3. 用户偏好表（替代 JSON 文件）
CREATE TABLE user_preferences (
    user_id           VARCHAR(64) PRIMARY KEY,
    travel_style      TEXT[] DEFAULT '{}',
    budget_level      VARCHAR(20) DEFAULT '舒适型',
    hotel_preference  TEXT[] DEFAULT '{}',
    liked_activities  TEXT[] DEFAULT '{}',
    disliked_activities TEXT[] DEFAULT '{}',
    cuisine_preference TEXT[] DEFAULT '{}',
    transport_priority TEXT[] DEFAULT '{性价比,时间}',
    extra             JSONB DEFAULT '{}',   -- 灵活扩展字段
    updated_at        TIMESTAMP DEFAULT NOW()
);

-- 4. 对话摘要归档
CREATE TABLE conversation_summaries (
    id            SERIAL PRIMARY KEY,
    user_id       VARCHAR(64) NOT NULL,
    session_id    UUID REFERENCES chat_sessions(id),
    summary       TEXT NOT NULL,           -- 压缩后的摘要
    key_points    TEXT[],                  -- 关键信息点
    created_at    TIMESTAMP DEFAULT NOW()
);
CREATE INDEX idx_summaries_user ON conversation_summaries(user_id, created_at DESC);

-- 5. 旅行历史
CREATE TABLE travel_history (
    id            SERIAL PRIMARY KEY,
    user_id       VARCHAR(64) NOT NULL,
    session_id    UUID REFERENCES chat_sessions(id),
    destination   VARCHAR(100),
    origin        VARCHAR(100),
    travel_date   DATE,
    travel_days   INT,
    budget        NUMERIC(10,2),
    plan_summary  TEXT,                    -- 行程摘要
    status        VARCHAR(20) DEFAULT 'planned',  -- planned/completed/cancelled
    created_at    TIMESTAMP DEFAULT NOW()
);
CREATE INDEX idx_history_user ON travel_history(user_id, created_at DESC);
```

## 5. 各模块职责

| 文件 | 职责 | 对外接口 |
|------|------|---------|
| `memory/working.py` | 当前请求的推理状态，按session隔离，请求结束清除 | `update()`, `get_context()`, `clear()` |
| `memory/short_term.py` | Redis存最近20轮，TTL 30min，Redis挂时降级到dict | `add_message()`, `get_history()`, `get_context_window()` |
| `memory/long_term.py` | 聚合PG偏好 + PG摘要 + Chroma RAG 的读写 | `get_preferences()`, `search_knowledge()`, `get_travel_history()` |
| `memory/router.py` | 根据请求内容决定注入哪些记忆 | `load_context(session_id, user_query) → dict` |
| `memory/promotion.py` | 请求结束后提取重要信息写入长期记忆 | `promote(session_id, messages) → None` |
| `db/postgres.py` | asyncpg连接池管理 | `get_pool()`, `execute()`, `fetch()` |
| `db/models.py` | 聊天记录/偏好/摘要/历史的CRUD | `save_message()`, `get_session_history()`, `update_preferences()` |

## 6. 记忆路由器核心逻辑

```python
# memory/router.py

class MemoryRouter:
    async def load_context(self, session_id: str, user_id: str, user_query: str) -> dict:
        """根据请求内容，决定从哪些层加载记忆"""

        context = {}

        # 1. 工作记忆：总是加载
        context["working"] = self.working_memory.get_context(session_id)

        # 2. 短期记忆：session有历史时加载
        short_history = await self.short_term.get_history(session_id)
        if short_history:
            context["short_term"] = short_history

        # 3. 长期记忆：按需加载
        #    - 涉及偏好关键词 → 加载用户画像
        #    - 涉及"上次/之前" → 加载旅行历史
        #    - 涉及具体城市/景点 → 检索RAG知识库
        if self._needs_preferences(user_query):
            context["preferences"] = await self.long_term.get_preferences(user_id)

        if self._needs_history(user_query):
            context["travel_history"] = await self.long_term.get_travel_history(user_id, limit=5)

        if self._needs_knowledge(user_query):
            context["knowledge"] = await self.long_term.search_knowledge(user_query)

        return context
```

## 7. 请求生命周期（完整流转）

```
用户发消息: "帮我规划去杭州3天，预算3000"
│
│ ① 写入 PostgreSQL (chat_messages) — 持久化原始消息
│
▼
Memory Router 加载记忆:
├── 工作记忆: {} (新请求，空的)
├── 短期记忆: ["上一轮:我想去江浙", "助手:推荐杭州/苏州/南京"] (Redis)
├── 长期记忆:
│   ├── 用户偏好: {liked: ["古镇"], budget: "舒适型"} (PG)
│   └── 旅行历史: ["2025年去过苏州2日游"] (PG)
│
▼
注入 LangGraph GlobalState → Main → Planner → Executor → Summarizer
│
▼
请求结束，写回Pipeline:
│
├── ② 写入 PostgreSQL (chat_messages) — 存助手回复
├── ③ 写入 Redis — 更新短期上下文
├── ④ ContextCompressor 评估 — 需要压缩吗？
├── ⑤ Promotion 评估:
│   ├── 发现新偏好"预算3000" → 更新 PG user_preferences
│   ├── 本轮摘要 → 写入 PG conversation_summaries
│   └── 行程规划完成 → 写入 PG travel_history
│
▼
返回响应给前端
```

## 8. 与现有代码的集成点

| 现有组件 | 改动方式 |
|---------|---------|
| `GlobalState` | 新增 `memory_context: Optional[dict]` 字段，存 Router 注入的记忆 |
| `main_agent_node` | 入口处调用 `MemoryRouter.load_context()`，注入到 state |
| `final_output_node` | 结束时调用写回 pipeline（PG + Redis + Promotion） |
| `ContextCompressor` | 保留，作为 Promotion 的子步骤使用 |
| `UserProfileManager` | 逐步替换为 `memory/long_term.py` 中的 PG 实现 |
| `TravelRAG` | 不动，被 `memory/long_term.py` 聚合调用 |
| `config/settings.py` | 新增 `REDIS_URL`, `DATABASE_URL` |
